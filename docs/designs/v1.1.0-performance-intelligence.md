## Feature Specs

### 1. Per-app battery attribution
**User value:** Answers "what's draining my battery" with real numbers per app since last full charge.

**Source:** `BatteryStatsManager.getBatteryUsageStats()` (API 31+). Fallback for API 26-30: parse `dumpsys batterystats --charged` via Shizuku.

**UI:** New list under Battery screen → "Since last charge (18h ago)". Top 10 apps, bar chart, % battery consumed.

**Happy path:** `BatteryStatsManager` returns `List<UidBatteryConsumer>` → map UID to package → render.

**Shadow paths:**
- API < 31 && no Shizuku → show "Requires Shizuku on Android 11 or earlier" banner
- `SecurityException` on `BATTERY_STATS` perm → request via Shizuku, or show graceful degrade
- Empty list (device just booted) → "Data will appear after a few hours of usage"
- App uninstalled between measurement and render → skip, don't crash

**Error classes:** `SecurityException`, `IllegalStateException`, `PackageManager.NameNotFoundException`

**Permission:** `<uses-permission android:name="android.permission.BATTERY_STATS" tools:ignore="ProtectedPermissions" />` (Shizuku-granted)

### 2. Longitudinal score tracking
**User value:** "Is my phone getting worse?" — yes/no with visual proof.

**Storage:** Extend existing Room DB. New entity `ScoreSnapshot(id, timestamp, batteryScore, storageScore, ramScore, cpuScore, bloatwareScore, overallScore)`. Index on timestamp DESC.

**Trigger:** On every Diagnose run, write snapshot. Background WorkManager task runs daily at 3am if user hasn't diagnosed in 24h.

**UI:** New "Trends" tab in bottom nav OR Home card "Last 7 days ↗ +3 pts". Line chart via Canvas (no external dep — stay lean).

**Retention policy:** Keep 90 days raw, then daily averages for 1 year, then delete. Cap at 500 rows.

**Edge cases:**
- First run → "Come back tomorrow for your first trend"
- 1 point (first snapshot) → show single dot, tooltip "Keep using — trend appears after 3 days"
- Clock changed → detect monotonicity break, flag but don't crash
- DB migration: versionCode bump, use `Room.Migration`

### 3. Weekly health notification
**User value:** Reason to return.

**Mechanism:** `PeriodicWorkRequest` via WorkManager, every 7 days. Runs quick diagnose, composes notif: *"Weekly health: 3 issues found, 2 auto-fixable."* Tap → opens Diagnose screen.

**Content variations (rotate):**
- Issues-focused: "3 slow apps detected"
- Trend-focused: "Battery score dropped 6 points"
- Action-focused: "240MB can be freed now"
- Praise: "Phone health stable — 82/100"

**Channel:** `weekly_health` — importance LOW (no sound), category REMINDER.

**Opt-out:** First-run settings screen with toggle. Default ON.

**Permission:** `POST_NOTIFICATIONS` (API 33+) — request on install via Compose dialog.

**Edge cases:**
- User disabled notifs in system settings → detect, offer in-app reminder instead
- Worker fails repeatedly → exponential backoff, max 3 retries
- Device in Doze → use `setRequiresBatteryNotLow = false`, acceptable daily skip

### 4. OEM bloatware catalog
**User value:** Samsung users see Bixby/Samsung Pay/Galaxy Store flagged with *exact* savings. Pixel users don't see those false positives.

**Data source:** `assets/bloatware/` YAML files. Per-OEM: `samsung.yaml`, `xiaomi.yaml`, `oneplus.yaml`, `oppo.yaml`, `realme.yaml`, `generic.yaml`. Schema:
```yaml
- package: com.samsung.android.bixby.agent
  name: Bixby Voice
  severity: moderate     # light | moderate | heavy
  safe_to_disable: true
  ram_mb: 80
  battery_pct: 2.3
  notes: "Samsung's voice assistant. Disabling hides the Bixby button action."
```

**Detection:** At app launch, read `Build.MANUFACTURER`, load matching YAML + `generic.yaml`.

**UI:** Bloatware screen shows per-OEM count + generic count. Each entry: icon, name, severity chip, "Disable" button (via Shizuku `pm disable-user`).

**Community-editable:** YAML files in `assets/bloatware/`. Accept PRs from users. Version the YAML so future updates via in-app fetch become possible (v1.2.0).

**Parse lib:** `org.yaml:snakeyaml:2.2` (~350KB, acceptable).

**Edge cases:**
- Unknown OEM → fallback to generic.yaml only
- YAML malformed → log Crashlytics, fall back to empty list, don't crash
- Package not installed (bloat varies by region) → filter out pre-render
- Already-disabled packages → show as "Disabled ✓", offer re-enable

### 5. Shareable report card
**User value:** Flex your benchmark. Acquisition loop.

**Design:** PNG generated via Compose `captureToImage` or Canvas. 1080x1920 portrait. Contains:
- Device model + Android version
- Overall score (big)
- Sub-scores (battery/storage/RAM/CPU)
- "Android Doctor v1.1.0 · androidoctor.app"

**Trigger:** After benchmark run → "Share score" button. After diagnose → "Share report".

**Mechanism:** Create bitmap, save to `MediaStore.Downloads` (no perm needed), `Intent.ACTION_SEND` with image URI.

**Edge cases:**
- Gallery app missing → fallback to `ACTION_VIEW`
- User cancels share → toast "Saved to Downloads"
- Low storage → show toast, skip save

### 6. Quick Settings tile
**User value:** One-tap score glance. Stickiness driver.

**Mechanism:** `TileService` class. Shows score + color-coded icon. Tap → opens Home screen.

**State refresh:** Every hour via WorkManager updates tile text via `qsTile.label`.

**Add instructions:** First-launch onboarding shows "Pull down QS → edit → add Android Doctor tile" with animation.

**Edge cases:**
- No recent diagnose → tile shows "Tap to diagnose"
- Tile removed by user → no-op, don't nag

## Security & Threat Model

**Attack surface added:**
- New permission: `BATTERY_STATS` (Shizuku-granted only)
- New permission: `POST_NOTIFICATIONS` (user-granted, API 33+)
- New Intent filter: `ACTION_SEND` (outgoing only, no intent-filter exposed)
- New TileService (system binds, protected by `android.permission.BIND_QUICK_SETTINGS_TILE`)

**Mitigations:**
- Package names in bloatware YAML are public knowledge (no secret)
- No network calls added — Firebase already handles attribution
- Report card includes device model + version only, no PII
- Score snapshots stored in app-private DB, deleted on uninstall

**LLM-injection:** N/A (no LLM calls)
